# 운영 가이드 (OPERATIONS)

## 컨텍스트 조립 방식
매 응답마다 서버가 다음 순서로 프롬프트를 조립한다(계획서 4.1):

```
시스템 규칙 → 캐릭터 카드 → 페르소나 → 장면 카드 → 고정 기억 → 활성 로어 → 요약 → 최근 N개 대화 → 현재 입력
```

토큰 예산은 `CONTEXT_TOKENS` 에서 응답 예약분(`profile.max_tokens` + 여유)을 뺀 값을 나눠 배분한다. 출발점 비율:
- 고정 블록(규칙+카드+페르소나+장면) **25%**
- 활성 로어 **15%**
- 고정 기억+요약 **15%**
- 최근 대화 **나머지 45%+여분**

예산을 초과하면 순서대로 자동 축약된다: 캐릭터 카드의 **예시 대화가 먼저** 잘리고, 로어는 우선순위 낮은 항목부터 제외, 최근 대화는 오래된 것부터 탈락한다. 채팅 화면 우상단 **▤(서랍) → 컨텍스트** 탭에서 이번 턴의 실제 배분·활성 로어·조립된 프롬프트 원문을 그대로 확인할 수 있다.

### 토큰 추정과 보정
로컬 모델의 정확한 토크나이저 없이, 한글은 글자당 약 0.7토큰 등 언어별 계수로 추정한다. 응답에 실제 `usage.prompt_tokens` 가 오면 추정 대비 실측 비율로 보정계수(EMA)를 갱신한다. 몇 번의 대화 후 예산 계산이 실제와 수렴한다. 서랍의 `보정계수 ×N.NN` 이 그 값이다.

## 기억(Memory) 워크플로
자동 기억은 **후보 → 사용자 승인** 단계를 반드시 거친다. 모델이 멋대로 장기 기억을 심지 않는다.

1. 서랍 → **요약** 탭 → "지금까지 대화 요약하기": `summary` 프로필로 요약 **초안**과 기억 **후보**를 생성한다. 마지막으로 승인된 요약 이후의 새 메시지만 대상으로 한다.
2. 요약을 검토·편집 후 **승인**하면 이후 프롬프트의 "요약" 자리에 들어간다.
3. 서랍 → **기억** 탭에서 후보를 **채택/버림**. 채택된 항목만 "고정 기억"으로 주입된다. 직접 추가도 가능하다.
4. 기억 범위(scope): `conversation`(이 대화 전용) 또는 `character`(같은 캐릭터의 모든 새 대화에서 공용).

권장 리듬: 대화가 길어져 최근 창이 꽉 차기 전에 한 번씩 요약·승인 → 오래된 원문이 탈락해도 맥락이 요약으로 보존된다.

## 분기·스와이프·편집
메시지는 트리로 저장된다.
- **재생성/스와이프**: 같은 지점에서 만든 여러 응답은 형제(swipe)로 남는다. 말풍선을 좌우로 밀거나 `‹ 1/3 ›` 로 전환한다. 마지막 응답에서 오른쪽 끝을 넘기면 새로 재생성한다.
- **사용자 메시지 편집 → "저장 후 재생성"**: 같은 부모 아래 새 분기를 만들고 이어서 생성한다(원래 흐름은 형제로 보존).
- **어시스턴트 메시지 편집 "저장"**: 내용만 교체(수동 교정용).
- 활성 분기(head)만 프롬프트에 반영된다. 내보내기 JSON 에는 전체 트리가 포함된다.

## 모델 프로필 튜닝
설정 → 모델 프로필. RP 대화에 쓰는 두 개:
- `rp-balanced` (temp 0.8): 일관성 우선. 기본 채팅.
- `rp-creative` (temp 1.0): 전개·묘사 풍부. 스토리 모드 기본.

내부 전용:
- `summary` (temp 0.3): 요약/기억 추출용. JSON 출력.
- `memory-extract` (temp 0.2): 예비.

각 프로필에서 `model`(비우면 서버 기본), temperature, top_p, max_tokens, stop, **시스템 주입 방식**을 조절한다. 시스템 역할을 지원하지 않는 모델이면 주입 방식을 **merge**(첫 user 메시지에 규칙 병합)로 바꾼다.

## 스토리 모드
대화 설정에서 모드를 **스토리** 로 두면, 응답 말미에 `<choices>[...]</choices>` 형식으로 최대 3개 선택지를 함께 생성하도록 유도한다. 파싱에 성공하면 본문 아래 칩으로 표시되고, 탭하면 입력창에 채워진다. 파싱 실패 시 본문만 표시되므로 흐름이 끊기지 않는다.

## OOC (캐릭터 밖 대화)
사용자 메시지를 `(OOC: ...)` 또는 `[OOC: ...]` 로 시작하면, 그 턴은 캐릭터 연기를 벗어나 메타 지시로 처리된다. OOC 쌍은 이후 프롬프트의 최근 대화에서 자동 제외되어 롤플레이 맥락을 오염시키지 않는다.

## 콘텐츠 지침
설정 → 콘텐츠 지침. 전 대화 공통으로 시스템 규칙에 삽입되는 문구(톤·수위·금지 등). **미성년자 보호 등 핵심 안전 규칙은 이 값과 무관하게 항상 강제**된다.

## 백업·복원
SQLite(WAL) 단일 파일이 전부다. **이 배포는 docker 를 쓰지 않는다** — systemd `--user` 서비스로
직접 실행한다 (호스트에 docker 자체가 설치되어 있지 않음, 2026-08-24 확인).

```bash
# 백업: systemd --user 타이머가 매일 04:00 자동 실행 (RandomizedDelaySec=120).
systemctl --user list-timers rpchat-backup.timer
systemctl --user cat rpchat-backup.service   # ExecStart: python3 deploy/backup-host.py
# 수동 1회 실행:
systemctl --user start rpchat-backup.service
# 산출물: /home/hermes/rpchat/backups/rpchat-YYYYMMDD-HHMMSS.db.gz (WAL-safe sqlite3 .backup, KEEP_DAYS=14)

# 복원 (호스트 경로 기반, 라이브 서비스는 스크립트가 직접 중지/재기동한다):
deploy/restore.sh /home/hermes/rpchat/backups/rpchat-YYYYMMDD-HHMMSS.db.gz
```
`restore.sh`는 실행 전 `PRAGMA integrity_check`와 conversations/messages 건수를 raw로 보여주고,
`yes` 확인 후에만 `rpchat.service`를 멈추고 교체한다. 교체 직전 현재 라이브 상태를
`rpchat-pre-restore-<timestamp>.db`로 같은 백업 디렉터리에 안전판으로 남긴 뒤 복원이 잘못됐을 때
그 파일로 되돌릴 수 있게 한다. `deploy/backup.sh`·`deploy/docker-compose.yml`은 이전 docker 배포
방식의 유물로 **현재 배포에서 쓰이지 않는다** — 실제 백업 산출은 `backup-host.py`가 전부다.

2차(오프호스트) 백업 사본 경로는 아직 없다 — 이 호스트 디스크 장애 시 백업까지 함께 소실된다.

앱 내 **설정 → 내보내기** 또는 `/api/export/all` 로 전체 JSON 백업도 가능하다(캐릭터·대화·기억 등).

## 헬스·모니터링
- `GET /api/health`: db/모델 상태, 해석된 모델명, 활성 생성 수, 프롬프트 버전.
- `GET /api/generation-log?limit=50`: 최근 생성의 추정/실측 토큰, TTFT, 총 소요, 예산 스냅샷. 프롬프트 버전별 회귀를 추적할 때 쓴다.
- 설정 화면 상단에서 모델 연결·지연·사용 가능 모델 목록을 즉시 확인.

## 문제 해결
| 증상 | 확인 |
|---|---|
| "모델 서버에 연결되지 않았습니다" | `MODEL_BASE_URL` 정확성, Mac 의 `tailscale serve status`, 모델 서버 기동 여부. `curl $MODEL_BASE_URL/models`. |
| 401 / 접근 불가 | tailscale 모드면 Serve 경유 접속인지·`ALLOWED_LOGIN` 일치 여부. token 모드면 HTTPS(Serve) 경유인지(쿠키 Secure). |
| 응답이 중간에 끊김 | 클라이언트 네트워크 단절이어도 서버 생성은 지속되어 저장된다. 화면은 자동 재동기화하며, 중단하려면 "생성 중단"을 눌러야 서버 측 생성이 취소된다. |
| 한글 토큰 예산이 안 맞음 | 몇 턴 지나면 보정계수가 수렴. 급하면 설정에서 `token_calibration` 수동 조정. |
| 컨텍스트가 금방 참 | 요약·승인으로 오래된 원문을 대체. 캐릭터 예시 대화 축소, 로어 `token_cap` 하향. |
| system 역할 오류 | 프로필의 시스템 주입 방식을 merge 로 변경. |

## 첫 배포물의 범위(의도적 제외)
음성/TTS, 이미지·영상, 캐릭터 마켓/공유, 결제, 다중 사용자, 소셜 로그인은 1차 범위에서 제외했다. 목표는 "캐릭터 한 명과의 긴 대화를 안전하게 이어가는 모바일 PWA" 다.
