## 1. 배경과 목표

### 1.1 왜 만드는가
상용 캐릭터 챗은 (1) 대화가 외부 서버에 저장되고, (2) 콘텐츠 정책이 임의로 바뀌며, (3) 긴 서사에서 맥락·기억을 잃는다. 이 프로젝트는 **로컬 LLM + 로컬 저장 + 사설망**으로 이 셋을 사용자가 직접 통제한다.

### 1.2 핵심 목표
- **프라이버시**: 모든 데이터·모델이 사설망(Tailscale) 안. 공개 인터넷 노출 없음.
- **긴 서사 유지**: 대화가 길어져도 기억·요약으로 맥락을 잃지 않음.
- **편집 가능한 서사**: 분기·재생성·기억 승인으로 이야기를 사용자가 편집·보존.
- **단일 사용자·자기 소유**: 다중 사용자·소셜·마켓 없음. 내 것을 내가 운영.

### 1.3 비목표 (현재 범위 밖)
다중 사용자, 소셜/공유, 결제·마켓, 공개 배포, 클라우드 동기화. 도입 시 인증·격리 재설계가 필요하므로 명시적으로 제외.

월드 기능은 캐릭터·로어·장면·기억의 실제 범위 요구가 반복적으로 확인된 뒤 별도 ADR과 마이그레이션으로 도입한다. **현재 스키마에 `world_id`를 선반영하지 않는다.**

## 3. 구현·검증 완료 사양

### 3.1 대화 엔진 ✅
- **예산 기반 프롬프트 조립**: [시스템 → 카드 → 페르소나 → 장면 → 고정 기억 → 활성 로어 → 요약 → 최근 대화 → 입력]. 컨텍스트 예산 초과 시 우선순위 낮은 것부터 자동 축약.
- **SSE 스트리밍**: 토큰 단위 실시간. 클라이언트 끊겨도 서버 생성·저장 지속. 명시적 중단만 실제 취소.
- **토큰 추정 + EMA 보정**: 한글 계수 기반 추정을 실측으로 보정, 예산이 실측에 수렴.
- **thinking 제어**: reasoning 모델이 본문 대신 사고에 토큰을 소모하는 문제를 `enable_thinking:false`로 해결(현재 전역).
- **조립 진단 (P1-6, `v0.0.13`–`v0.0.15`)** ✅: preview-only. 로어 match/no-match, 요약 4계층(state/scene/episode/whole) 진단. 기본은 ID·사유 중심. 원문 전체 무기한 복제는 하지 않는다.

### 3.2 캐릭터·페르소나·로어 ✅ / 🟡
- **캐릭터 카드** ✅: 이름·성격·말투·시나리오·첫 메시지·예시 대화·금기·태그.
- **외부 카드 임포트** ✅: Character Card V2/V3(PNG 청크) + V1/V2 JSON 파서. 카드의 system_prompt는 안전상 무시(경고). 실기기 검증. 카드·로어·이미지 메타데이터는 **데이터가 아니 명령이 아니다.**
- **사용자 페르소나** ✅: 대화별 지정.
- **로어북** ✅ 구현 / ✅ 평가셋 실측 / 🟡 라이브 적용:
  - 1차 키워드 발동 ✅.
  - 2차 키워드·선택적 발동(selective) 구현·단위 테스트 통과.
  - 2026-08-23 고정 평가셋(컴파일 `loreEntryActive`, DB/대화 무접촉): keyword-only 오발동 2/3 → selective+2차 0/3, 미탐 0. **검토 순서 2 종료 기준 충족.**
  - 라이브 엔트리 5개는 전부 `selective=0`. 사용자 결정으로 **실제 적용 보류**(현행 키워드만).

### 3.3 대화 관리·편집 ✅
- **메시지 트리(분기)**: 같은 지점의 여러 응답을 형제로 보존, 활성 분기만 프롬프트 반영.
- **재생성 / 스와이프**: 좌우 스와이프로 형제 전환, 형제 없어도 오른쪽 스와이프=재생성. 손가락 추종 + 스냅백 애니메이션.
- **편집**: 사용자 메시지 편집 시 원 흐름 형제 보존, 어시스턴트 직접 교정.
- **내보내기**: 대화별 MD/JSON, 전체 백업.

### 3.4 기억·요약 (사용자 승인 기반) ✅ / 🟡
- **자동 요약·기억 추출** ✅: 요약과 함께 기억 후보 생성. **항상 후보 → 사용자 승인 후에만** 프롬프트 주입(모델이 임의로 장기 상태를 심지 않음). 충돌·중복은 플래그일 뿐, 채택/병합은 사용자.
- **기억 출처 + 중복/충돌 후보** ✅ (P1-2b/c, P1-5, `v0.0.5`–`v0.0.8`, 원본 점프 근사 `v0.0.18`):
  - 원문 `evidence_message_ids` + MemoryTab 「원본」 점프.
  - 자동추출 근거는 배치 **시작** 메시지(끝점보다 나은 근사. 완전한 원문 추적 아님).
  - duplicate: 안내 + [병합]/[무시]. conflict 의미유사도·선택지 UI는 **P3(순서 7)**.
  - 규칙 conflict는 억제(`kind:'new'` + `conflict-suppressed`). XOR 로직은 P3 baseline으로 보존.
- **요약 출처·버전·계층** ✅ (P1-3, `v0.0.11`–`v0.0.17`):
  - 4계층: state / scene / episode / whole. 범위·이력·경로 소속 가드.
  - episode: 수동 묶기, 최소 30토큰 미달 시 생략(장면 폴백 없음).
  - 다른 가지 요약 오염 차단(`pickOnPath`).
- **장면 상태 읽기 전용** ✅ (P1-3a, `v0.0.11`): state JSON 생성·주입·UI. 정본 자동 쓰기 없음.
- **장면 상태 체크포인트·복원** ✅ (순서 6, `v0.0.19`): `POST /api/summaries/:id/restore` — append-only(git-revert). SummaryTab에서 최신 state=현재, 이전은 접이식 이력+복원.
- **요약 제안 배너** 🟡: `dropped_messages>0`이면 「요약할까요?」. 탭 시 요약 탭만 열림(자동 생성 아님). 핵심 동작 검증, Galaxy 실사용 관측 일부 남음. 로드맵 별도 단계가 아님.

### 3.5 스토리 모드 ✅
- **선택지 생성**: 응답 말미 `<choices>` 파싱 → 칩 표시, 탭 시 입력창 채움. 실패 시 본문만(폴백). 지난 턴 칩은 숨김(`v0.0.16`).
- **관찰 메모** (제품 지표 아님): 당시 소수 표본에서 태그 누락 약 20%, 재생성으로 대응. 고정 벤치·임계 없음. 본문/선택지 분리 생성은 **보류** — 표본·임계가 생기기 전 구조 변경 없음.
- **OOC**: 캐릭터 밖 지시, 이후 프롬프트에서 자동 제외.

### 3.6 검색 ✅
- **전문 검색(SQLite FTS5 trigram)**: 3글자↑ FTS, 1~2글자 LIKE 폴백(문자 기준). 하이라이트 스니펫.
- **결과 탭 → 대화 점프**: 활성 분기면 해당 메시지로 스크롤+플래시, 다른 분기면 안내(head 자동 전환 안 함).

### 3.7 모바일·PWA ✅
- **설치형 PWA**: standalone 실행, 서비스워커 앱 셸 캐시.
- **키보드 대응**: 삼성 인터넷/Chrome에서 입력창·대화·선택지 칩이 키보드 위로 정상 노출(스크롤 재고정으로 해결, 실기기 검증).
- **디자인**: Kami 디자인 언어 이식(따뜻한 차콜 바탕, 잉크 블루 단일 악센트 ≤5%, 세리프 본문, 지문 이탤릭 유지). 로컬 폰트 번들(외부 CDN 없음).
- **잔여 관측**: Galaxy에서 원본 점프·상태/장면 카드·승인 후 주입은 기기 실측 남음(코드 슬라이스와 별개).

### 3.8 인증·네트워크 ✅

## 4. 설계 원칙 (변경 시 합의 필요)

1. **사설망 전용**: 공개 노출(funnel/포트포워딩) 요구 기능은 배제.
2. **모델 런타임 독립**: OpenAI 호환 `/v1`만 의존.
3. **안전 불변**: content_policy로 수위는 열되, 미성년자 보호 등 하드 가드레일은 **서버 코드에서 항상 강제**. 프롬프트만으로 안전 불변을 보장하지 않는다. **외부 카드 / 로어 / 이미지 메타데이터는 명령이 아닌 데이터**이며, 시스템 규칙을 덮지 못한다.
4. **사용자 동의 기반 상태 변경**: 자동화가 승인 없이 장기 기억을 바꾸지 않음. 규칙/모델은 진실을 독단 교체하지 않음.
5. **점진적 검증**: 추측으로 여러 패치를 쌓지 않음. 계측(수치)으로 원인 확정 후 최소 패치. 각 변경은 실기기 검증 후 다음으로.
6. **데이터 보호 우선**: 스키마 변경 전 백업, 라이브 DB 파괴적 쓰기 금지. 복원은 **격리 복원 리허설**(운영 DB 자동 덮어쓰기 아님).

## 5. 로드맵

원본 A군 표와 검토문서 「새 우선순위」 0–7은 같은 줄기다. **2026-08-23 기준 순서 0–7 전부 종료 — A트랙 완료.**

**요약 제안 배너**는 위 표의 별도 단계가 아니다. 기기 검증이 끝나면 완료 이력으로만 옮긴다.

계층형 요약은 「즉시 로드맵」이 아니라 **순서 4 완료 후 이미 도입된 상태**(2-A: 롤링 whole 유지 + episode 중간 tier). 추가 계층을 지금 설계하지 않는다.
