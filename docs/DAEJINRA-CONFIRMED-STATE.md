# 대진라: 사용자가 확인한 상태와 콘텐츠 교정

스토리 대화 후보에서 **장면 상태 → 등록·의뢰·소지품 확인** 화면을 연다. 이 문서는 로컬 이식 후보의 설명이다. 이 API는 아직 배포되지 않았다. 활성 참여자가 두 명 이상이고 마지막 응답이 완료된 대화에서 사용할 수 있다. 등록 여부, 통화·잔액, 의뢰 단계, 소유품·대여품, 경지·경험치·능력은 사용자가 입력하고 확인한 뒤에만 기록한다. 모든 기록은 공개 정보다.

## 사용 흐름

1. 현재 통화 단위·잔액·경지·경험치·능력을 확인하고 기록을 시작한다. 기존 대화에서 값을 자동 추출하지 않는다.
2. 등록 완료와 실제 등록비, 지급·수령, 의뢰 제안과 단계 변경, 실물 수령과 반납을 각각 기록한다. 이미 등록한 인물의 현재 상태를 옮길 때는 등록비를 다시 차감하지 않도록 납부액 0으로 등록을 기록한다.
3. 의뢰 완료와 보수 수령은 별도다. 제안 보수가 아니라 실제 수령액으로 정산하며, 정산을 반복할 수 없다. 대여품은 소유자·제공자·반납 조건을 함께 기록한다.
4. 잘못 확인한 기록은 해당 확인 턴을 삭제한 뒤 다시 입력한다. 삭제는 그 이후 하위 대화도 지우는 기존 메시지 삭제 동작을 따른다. 다른 분기로 이동하면 그 분기에 저장된 상태가 복원된다.

확인 기록은 사용자 행동과 서버 영수증으로 이루어진 일반 대화 턴이다. 문장 편집·재생성·이어쓰기로 기록 내용을 바꿀 수 없다. 확인 직후 새 메시지를 보내면 해당 상태를 바탕으로 이야기가 이어진다. 환율, 고정 물가, 자동 XP·승급 규칙은 없다. 질문·추천 답변·모델 서술을 실제 행동으로 해석하지 않는다.

이 기능을 켠 분기에서는 모델의 금액·소지품·의뢰·등급 변경을 적용하지 않는다. HP·시간·장소 등 기존 장면 전이는 계속 사용한다. 기록되지 않은 사실과 모델 서술의 정확성까지 검증하는 기능은 아니다.

## 저장과 검증

- 후보의 `POST /api/conversations/:id/adventure-actions`는 명시적인 action, 기대 head·scene version, 멱등 키를 받는다. 이 경로는 배포 전이다. 같은 요청 재시도는 같은 영수증만 돌려주며 현재 분기를 이동시키지 않는다.
- 기존 `scene_json`과 메시지 snapshot/meta에 저장한다. 신규 테이블·마이그레이션이나 path-memory 승인 anchor를 만들지 않는다.
- 상태 한도는 의뢰 40개·물품 60개·능력 20개, 수량 10,000, 금액·XP 1,000,000,000이다. 이는 저장 검증 한도이며 세계관 규칙이 아니다.
- 확인 상태는 beat N/F/E와 dialog 요청에 예산 안에서 공개 데이터로 전달한다. 잘린 기록을 미보유·완료로 해석하지 않도록 표시한다. 기능을 쓰지 않는 분기와 1:1 프롬프트에는 이 데이터 절을 넣지 않는다.

`adventureState`, `adventureRoutes`, `adventureGeneration` 벤치는 합성 데이터와 고정 모델 대역을 사용한다. `bench/browser/adventure.ts`는 로컬 Chromium에서 실제 폼·확인 모달·API·저장 후 화면 갱신 실패 재시도를 검사한다. 실모델 서술 품질과 Galaxy 실기기 체감은 별도 검증이다.

## 콘텐츠 교정

2026-10-13 조사 인수인계에 따른 대진라 스토리 콘텐츠 교정은 이 저장소의 코드가 아니라 운영 DB에 별도 승인 작업으로 적용했다(2026-10-15, 스토리 4개 필드와 카드 4장, 모두 10개 필드). 서라운의 내륙·항구 단정 제거, 진휘의 공개 활동지와 이 재구성의 초기 배치 구분, 등록·의뢰·인도·반납·정산을 각각 확인하라는 상태 지침이 그 내용이다. 공개 편람을 이 구현에서 독립 검증했다는 뜻은 아니다.

원작자 쇠족제비와 원본·공개 편람 링크, 17명 카드 ID·9개 장소 ID·연결 순서, 기존 대화와 스냅샷은 바꾸지 않았다. 특정 조사 대화의 등록비·의뢰 보수·물품 조건을 공통 물가나 제도로 추가하지 않았다.

교정에 쓰던 스크립트와 교정 목록은 이 저장소에 포함하지 않는다. 적용 기록과 백업은 저장소 밖 운영 증거에 있다.
