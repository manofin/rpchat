## 4. 성공 기준 (채택 필요조건 — 후보1)

### 4.1 채팅 비저하
1. 이미지 요청 전후 Gemma TTFT p50 변화 ≤ 10%
2. 이미지 생성 동시 구간 Gemma TTFT p95 변화 ≤ 20%
3. tok/s p50 변화 ≤ 10%
4. 채팅 요청 오류율 증가 0%p

### 4.2 이미지 UX
1. 작업 접수 응답 ≤ 500ms
2. 생성 중 채팅 블로킹 0건
3. 사용자가 작업 상태를 확인할 수 있음
4. 실패 시 동일 장면에서 재시도 가능
5. 페이지 새로고침 후에도 작업 상태 복구
6. 사용자 요청 이후 결과 도착시간 p95 ≤ 30초 (경량 SDXL turbo/lightning 4–8스텝 가정,
   2026-08-24 확정)

### 4.3 운영 안정성
1. 요청 성공률 ≥ 95%
2. 타임아웃 요청이 채팅에 영향 없음
3. 워커 오프라인 시 빠른 실패 또는 명확한 대기 상태
4. 중복 클릭으로 동일 요청이 다중 생성되지 않음
5. 완료 이미지는 앱의 정적 저장소로 복사된 뒤 제공

### 4.4 Mac Studio 후보 전용
1. 스왑 증가 없음
2. Gemma 모델 축출 또는 재로딩 없음
3. 이미지 생성 전후 Gemma TTFT 콜드 스타트 없음
4. 이미지 생성 종료 후 메모리가 정상 회수됨
5. 이미지 동시 생성 중 TTFT p95 변화 ≤ 20% (4.1-2와 동일 항목, 카테고리 교차 확인용 중복 게재)

### 4.5 안전 (확정 2026-08-24 — unconditional 게이트, 성능 기준과 별개 필요조건)
1. 삽화 프롬프트는 사용자 자유 텍스트를 받지 않는다. 서버가 장면 상태(state JSON)/요약에서
   인물·배경·행동을 조립한다. 자유 텍스트 주입 경로 원천 차단.
2. 조립된 프롬프트는 서버 코드 금칙 패턴 필터(목록은 repo 내 버전 관리, 각 항목 근거 주석
   포함)를 통과해야 한다. 필터는 보조선 — 주 게이트는 (1)의 조립 방식.
3. 레드팀 픽스처 N케이스(카드/로어에 삽입된 프롬프트 인젝션 시도 포함 — "데이터는 명령이
   아니다" 원칙의 이미지 확장) 100% 차단, 우회 0.
**성능 기준(§4.1~4.4) 전부 통과해도 본 절 미충족이면 비채택.**

## 5. 판정 합산 규칙
- 4.1~4.4 **전부 충족**이 후보1 채택 필요조건. 하나라도 불충족 → 비채택.
- 4.5(안전)는 통과가 확정되기 전까지 별도 unconditional 게이트 — 정의 완료 후 소급 적용.
- θ류 사후 조정 금지(P3 §5 계승): 결과 확인 후 임계값 완화·재해석 금지.
- **비채택도 정상 결과**: 자원 경쟁 확인 = 근거 확보 = 후보1 종료. 후보2 착수는 본 벤치
  결과와 무관하게 사용자의 새 승인 필요(순차 게이트이므로 후보1 실패가 후보2를 자동 차단
  하지는 않으나, 같은 Mac 자원 제약이 적용되므로 근거 재검토 필요).
