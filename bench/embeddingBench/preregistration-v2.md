## 5-1. 실행 순서 및 C1 실패 처리 프로토콜 (§0-4 세부, 2026-09-01 확정)

**준비(prewarm)는 병렬, 실제 평가 실행은 조건부.** Task 0에서 C1/C2/C3 전부에 대해
모델 준비·입력·명령 초안 작성·출력 디렉터리 생성·실행 전 점검까지는 동시에 해도 되지만,
**C2/C3의 실제 평가 실행(raw 코사인 계산 및 판정)** 은 아래 트리를 따른다.

```text
C1 실행
├─ PASS
│  └─ C2 실행
│     ├─ PASS → H1_B_NOT_NEEDED / C3_NOT_RUN
│     ├─ FAIL → H1-b 활성화 / C3 실행
│     └─ NOT_EVALUABLE → H1_B_UNDECIDED / C3_NOT_RUN
│
├─ FAIL
│  └─ C2_NOT_RUN / H1_B_NOT_REACHED / C3_NOT_RUN
│
└─ NOT_EVALUABLE
   └─ C2_NOT_RUN / H1_B_UNDECIDED / C3_NOT_RUN
```

**핵심 원칙**: C1 FAIL은 "전체 분기 판단이 성립하지 않았다"는 신호로 처리한다 — H1-b를
여는 신호가 아니다. C1 FAIL을 C2 FAIL과 동일시해 C3로 우회하지 않는다.

### C1 실패 시 즉시 중단 항목
- C2 실제 실행 금지, C3 실제 실행 금지, H1-b 활성화 금지
- §4 성공 기준 변경 금지, 실패한 조건을 즉석 수정해 같은 토큰에서 재실행 금지
- 진행 중인 C3 prewarm(비파괴적 작업)도 가능한 한 중단 — 이미 받은 모델/구축한 격리
  환경은 삭제하지 않아도 되지만 결과 평가에는 쓰지 않는다

### C1 비통과의 3가지 분류 (하나의 `FAIL`로 뭉치지 않는다)
| 분류 | 예 | 상태 | 후속 |
|---|---|---|---|
| A. 진짜 가설 실패 | C1(H2-relative)이 §4 채택기준 자체를 못 채움 | `C1_FAIL` | C1을 고치는 새 과제 필요할 수 있음 |
| B. 환경 실패 | 의존성/모델파일 누락, 권한, 디스크, 네트워크, 실행경로 오류 | `C1_NOT_EVALUABLE` | 환경 문제 해결은 별도 새 토큰 |
| C. 사전등록/fixture 결함 | 입력셋 오류, 평가스크립트 불일치, 성공기준 계산불가, 결과파일 형식불일치 | `C1_INVALID` | 조용히 고치지 말고 정정기록/새 revision 필요 |

세 경우 모두 `C2_NOT_RUN`, `C3_NOT_RUN`. B는 `H1_B_UNDECIDED`, A/C는 `H1_B_NOT_REACHED`.

### 실패 증거 동결 (종료 전 최소 보존)
실행 명령·시작/종료 시각·commit(HEAD)·작업 환경·입력 fixture hash·설정 파일 hash·
stdout/stderr·종료 코드·생성된 부분 산출물·자원 상태·C1 판정 근거·C2/C3 미실행 증거.
부분 산출물을 정상 결과처럼 쓰지 않는다 — manifest/파일명에 `INCOMPLETE`/`INVALID`/
`NOT_EVALUABLE` 상태를 명시.

### C3 prewarm 산출물 처리 (C1 FAIL 시)
- **보존 가능**: 격리 venv, 다운로드된 모델, checksum, fixture 복사본, 미실행 명령
  스크립트, 출력 없는 작업 디렉터리 — 향후 별도 토큰에서 재사용 전 hash·환경 재검증
  조건으로 보존
- **사용 금지**: C3 핵심 생성/측정, C3 결과의 PASS/FAIL 판정, 제품 채택 근거 인용,
  "H1-b 활성화됨" 기록, C1 실패를 근거로 한 C3 자동 실행

### 재시도 정책
- **재시도 없이 종료**(별도 새 named lock 필요): 사전등록된 품질 게이트 실패, 구조적
  한계, 반복 가능한 동일 실패, 기준 미달의 정상 벤치 결과
- **같은 P3-v2 토큰 내 별도 실행(C1-R2)으로 1회 재평가 가능**: 명백한 명령 오타, 일시적
  파일 손상, 실행 환경 준비 누락, 외부 서비스 일시 장애, fixture wiring 오류, 평가
  스크립트 자체의 명백한 버그 — 이 경우도 `C1-R1`을 덮어쓰지 않고 `C1-R1=NOT_EVALUABLE`,
  `C1-R2=재실행` 형태로 이력을 남긴다.

### 토큰 계약 문구 (요약)
> C1이 PASS인 경우에만 C2를 실행한다. C1이 FAIL·INVALID·NOT_EVALUABLE이면 C2와 C3를
> 실행하지 않고 증거를 보존한 뒤 종료한다. C1 FAIL은 C2 FAIL로 간주하지 않으며 H1-b를
> 활성화하지 않는다. C3 prewarm 산출물은 격리 상태로 보존할 수 있으나 평가하거나 제품
> 결정에 사용하지 않는다. 환경 또는 시험 설계 문제의 수정과 재실행은 별도 새 토큰을
> 요구한다.
