## 1. 측정하는 질문

현행 `renderSceneDeltaPrompt`(캐스트 포함)만으로, 모델이 **보조 화자 난입 근거를 스스로 제안하는가.**

이것이 A안이다. 지금까지의 근거는 직접 프로브 n=1(`{"base_version": 6}`, 트리거 0)과
라이브 4턴(그중 2턴은 유키가 main이라 트리거 여부가 무관)뿐이므로, A의 실패율은 **미측정**이다.

## 2. 측정하지 않는 것

- 지연 (Token 3). 본 측정은 델타 콜 단독(`max_tokens 200`, 실측 ~3s)이라 본문 생성 구간과 무관하다.
- 라우터 정책의 타당성 (Token 4). `pickSpeaker`는 **읽기만** 하며 계약을 바꾸지 않는다.
- B안의 우열. A의 실패 모드가 보이기 전에는 비교 설계가 성립하지 않는다.
- 트리거가 만들어낸 대사의 품질. 본 측정은 발화를 생성하지 않는다.

## 3. 픽스처

라이브 캐스트를 그대로 쓴다: `한소연-smoke`(duty 등록·접수, main), `유키-smoke`(duty 보안·경비, secondary),
장소 `bureau_lobby`, 카탈로그는 라이브 story `F9-LIVE-PARTY-SMOKE`의 `scene_catalog`.

**유효성 필터 (필수).** 각 문장은 투입 전 `pickSpeaker`를 통과시켜 **주화자가 한소연인 것만** 채택한다.
주화자가 유키가 되는 문장은 유키를 secondary 후보에서 구조적으로 제외하므로 측정 대상이 아니다.
(Bench-A에서 도달분포를 코퍼스 구성비로 오인했던 실수를 반복하지 않기 위해, 이 필터는 결과가 아니라 **투입 조건**이다.)

| 버킷 | n | 구성 | 정답 |
|---|---|---|---|
| **T** trigger-warranted | 20 | 주화자=한소연, 내용이 보안·위험·경비와 명백히 닿음 | 유키에 대한 트리거 **있어야** 함 |
| **N** no-trigger | 20 | 주화자=한소연, 순수 행정·잡담. 위험 요소 없음 | 트리거 **없어야** 함 |

총 N = 40 콜. 온도 0.2 / top_p 0.9 / max_tokens 200 (제품 경로와 동일 파라미터).

## 4. 지표

- `recall_T` = (유키로 **해석 가능한** 트리거가 나온 T 건수) / 20
  - 해석 가능 = `parseSecondaryTriggers` 통과 + `auxGate`의 이름/alias 해석 성공
- `fp_N` = (트리거가 하나라도 나온 N 건수) / 20
- `malformed` = (JSON 파싱 실패 + 이름 미해석 + 사유 공백) / 40
- `base_version_ok` = base_version을 정확히 되돌려준 비율 / 40 (트리거 추가가 기존 계약을 깨뜨리는지)

`recall_T`의 분자는 **사유가 비어 있지 않은 것만** 센다. 사유 없는 트리거는 제품 게이트에서 침묵으로 떨어지므로 성공이 아니다.

## 5. 판정 (실행 전 고정)

```
ADOPT_A        : recall_T >= 0.60  AND  fp_N <= 0.20  AND  malformed <= 0.10
INSUFFICIENT_A : recall_T < 0.30
INCONCLUSIVE   : 그 사이
```

- `ADOPT_A` = A안만으로 trigger 공급이 성립한다. B안 설계 불필요.
- `INSUFFICIENT_A` = A안 단독으로는 성립하지 않는다. B안 또는 프롬프트 강화가 **별도 이름으로** 필요하다.
- `INCONCLUSIVE` = 프롬프트 강화 변형(A′) 측정이 **별도 이름으로** 필요하다.

`base_version_ok < 0.95`이면 판정과 무관하게 **회귀 경고**로 별도 보고한다
(트리거 노출이 기존 델타 계약을 훼손했다는 신호이므로).

어떤 결과가 나오든 이 잠금에서 제품 코드를 고치지 않는다. 판정은 사실이지 채택이 아니다.

## 6. 격리

- 라이브 DB는 `readonly` 접속으로 **읽기만**. 대화·메시지·scene 무접촉.
- 모델 서버는 추론 호출만(부작용 없음). 큐를 쓰지 않으므로 제품 생성과 경쟁하지 않도록 순차 실행한다.
- 결과는 `bench/triggerSupply/results/<ISO>.json`에 기록하고 sha256을 보고한다.
- 실행 스크립트는 `bench/triggerSupply/` 밖으로 나가지 않는다.
