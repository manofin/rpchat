## 2. A를 한 번 더 하지 않기 위한 설계 요건

A는 "빈 배열"과 "키 누락"을 구분하지 못했다. 그래서 실패 위치 4종(관련성 미인식 / 개입 불필요 판단 /
키 생략 / 우선순위 밀림)이 한 덩어리로 남았다. **본 측정은 관측 지점을 하나 추가한다.**

- 변형 프롬프트는 `secondary_triggers`를 **필수 키**로 요구한다. 끼어들 인물이 없으면 `[]`를 내야 한다.
- 이로써 `키 존재 여부`가 관측 가능해진다:
  - 키가 있고 `[]` → 모델이 고려한 뒤 **불필요로 판단**했다는 쪽으로 무게가 간다
  - 키가 아예 없음 → **키 생략 / 우선순위 밀림**이 확인된다

이 구분은 **진단 보고이지 채택 컷이 아니다.** 내부 사고를 보는 것이 아니라 출력 형태만 보는 것이므로,
"고려했다"의 직접 증거가 아님을 명시한다.

## 5. 지표

변형별로:

- `key_present_rate` = `secondary_triggers` 키가 존재한 비율 / 40  ← **신규 관측 지점**
- `recall_T` = 유키로 해석 가능하고 사유가 비지 않은 트리거가 나온 T 건수 / 20
- `fp_N` = 비어 있지 않은 트리거가 나온 N 건수 / 20
- `malformed` = (JSON 파싱 실패 + 이름 미해석 + 사유 공백) / 40
- `base_version_ok` = base_version 정확 비율 / 40

**`fp_N` 해석 규칙 (A의 설계 결함 교정).** A에서 `fp_N = 0`은 키가 한 번도 활성화되지 않은 데서
기계적으로 따라온 값이라 판별력이 없었다. 따라서 본 측정에서 `fp_N`은
**`key_present_rate ≥ 0.50`이고 해당 변형의 트리거 총량 > 0일 때만** 판정에 쓴다.
그 조건을 못 채우면 `fp_N = UNINTERPRETABLE`로 보고하고 ADOPT 판정에서 제외한다.

## 6. 판정 (실행 전 고정)

두 변형 중 **하나라도** 충족하면 그 변형 이름과 함께:

```
ADOPT_APRIME   : recall_T >= 0.60  AND  malformed <= 0.10
                 AND (fp_N <= 0.20  OR  fp_N == UNINTERPRETABLE)
INSUFFICIENT   : max(recall_T over variants) < 0.30
INCONCLUSIVE   : 그 사이
```

`base_version_ok < 0.95`이면 판정과 무관하게 회귀 경고로 별도 보고한다.

**진단(별도, 컷 아님)** — 두 변형의 `key_present_rate`로 실패 위치를 좁혀 보고한다:

```
key_present_rate 높고 recall_T 낮음  → "고려 후 불필요 판단" 쪽 무게 증가
key_present_rate 낮음                → "키 생략 / 우선순위" 확정에 가까움
```

이 진단은 원인을 확정하지 않는다. 출력 형태 관측일 뿐이다.
